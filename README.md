# YOTA · iPhone · Incy / Happ

Профили направляют сервисы из федерального белого списка YOTA в DIRECT, Apple и остальные сайты — через VPN. Рекламные домены блокируются. Российские доменные зоны и российские IP целиком в DIRECT не добавляются.

**Это маршрутизация для уже работающего VPN.** Она не предоставляет сервер и не делает доступным сервер, который оператор блокирует при ограничениях мобильного интернета.

## Incy: подключить автообновление

1. На iPhone открой [ссылку импорта как текст](https://raw.githubusercontent.com/pivazyaa/Routing-INCY-HAPP/main/dist/Incy-auto-import.txt) и скопируй её целиком.
2. Открой Incy и импортируй ссылку из буфера. Она начинается с `incy://autorouting/onadd/` и привязывает профиль к постоянному адресу.
3. В профиле «YOTA iPhone - Official WL + Apple VPN + Ads» проверь значок облака. В «Источник обновлений» выбери **12 часов**. Без изменения в интерфейсе стандартный интервал Incy — 24 часа.
4. Выбери свой VPN-сервер, включи маршрутизацию и переподключись.

Прямой адрес JSON: [Incy-YOTA-Whitelist.json](https://raw.githubusercontent.com/pivazyaa/Routing-INCY-HAPP/main/dist/Incy-YOTA-Whitelist.json).

Обычная ссылка `incy://routing/onadd/…` — разовый импорт. Она не заменяет ссылку `autorouting` для автоматического обновления.

## Happ: профиль и автоматическое обновление

Текущие правила можно импортировать из [Happ-import.txt](https://raw.githubusercontent.com/pivazyaa/Routing-INCY-HAPP/main/dist/Happ-import.txt). Выбери подписку, для которой они должны работать, активируй профиль и переподключись.

**Разовый импорт в Happ не включает автообновление белого списка.** Поддерживаемый документацией механизм — передача актуального профиля вместе с твоей подпиской VPN. Для этого:

1. Сервер подписки получает [актуальный профиль Happ](https://raw.githubusercontent.com/pivazyaa/Routing-INCY-HAPP/main/dist/Happ-YOTA-Whitelist.json) при формировании ответа.
2. В тело этой же подписки добавляются строки из [Happ-routing-body.txt](https://raw.githubusercontent.com/pivazyaa/Routing-INCY-HAPP/main/dist/Happ-routing-body.txt): интервал 12 часов и ссылка маршрутизации. В подписке обязательно остаются реальные серверы пользователя.
3. Happ обновляет подписку и вместе с ней профиль с тем же именем. После изменения настроек нужен Reconnect.

Файл `Happ-routing-body.txt` содержит **только добавку к подписке**, он не является самостоятельной VPN-подпиской. В текущей версии Happ правила принадлежат конкретной подписке; добавление отдельной пустой подписки не меняет маршрутизацию существующих серверов.

`happ_subscription.py` — готовая функция `combine(body, profile)` и утилита для владельца сервера подписки. Она поддерживает текстовые и base64-подписки со ссылками серверов, заменяет старую маршрутизацию и устанавливает интервал 12 часов. Результат должен обслуживаться по прежнему приватному HTTPS-адресу подписки. Старые HTTP-заголовки `routing`, `autorouting` и `routing-enable` на сервере тоже нужно убрать или заменить согласованными значениями.

Пример на сервере подписки, где `/srv/private-subscriptions` уже является приватным каталогом:

```sh
python happ_subscription.py --input /srv/private-subscriptions/upstream.txt --routing dist/Happ-YOTA-Whitelist.json --output /srv/private-subscriptions/happ.txt
```

Запускать при обновлении правил и исходной подписки. **Не размещай VPN-ключи, исходную подписку или результат этой команды в публичном репозитории.** Утилита отказывается записывать результат внутрь этого проекта.

Для полных JSON-конфигураций Happ действует отдельный режим: профиль поступает от провайдера, а его поля не переписывают автоматически маршрутизацию внутри самого Xray JSON. Такие конфигурации должен адаптировать владелец подписки. Недокументированная ссылка `happ://autorouting/…` здесь не используется.

## Что обновляется автоматически

GitHub Actions проверяет [официальную страницу YOTA](https://www.yota.ru/whitelist) каждые **6 часов**, в 00:17, 06:17, 12:17 и 18:17 UTC. Также запуск происходит при изменении кода/каталога и вручную через Actions → Update YOTA routing → Run workflow.

- `catalog.json` связывает проверенные названия сервисов с их доменами.
- `update.py` читает только карточки официального списка и привязанные к ним раскрывающиеся списки. Ссылки рекламы, меню и техническая разметка страницы не становятся DIRECT.
- Известный сервис появляется в списке — его домены добавляются. Исчезает — домены удаляются, если они не нужны другому разрешённому сервису.
- Пересобираются оба JSON-профиля, ссылки импорта и `LastUpdated`. Интервал на телефоне действует отдельно от расписания сборки.
- Подключается текущий релиз [Loyalsoldier/v2ray-rules-dat](https://github.com/Loyalsoldier/v2ray-rules-dat). SHA256 geosite проверяется по опубликованной контрольной сумме. Версионные адреса дают Incy сигнал скачать новые геофайлы. Happ может ограничивать их обновление одним разом в неделю; DIRECT находится непосредственно в JSON и не зависит от обновления geosite.
- При ошибке загрузки, повреждённой странице, отсутствующем раскрывающемся списке или внезапном исчезновении более 30% распознанных сервисов публикация останавливается: на телефоне остаётся предыдущая версия. Причина видна в Actions.

Проверенные результаты: [состав и время проверки](dist/status.json), [домены DIRECT](dist/direct-domains.txt), [упоминания без проверенных адресов](dist/review-needed.json), [история запусков](https://github.com/pivazyaa/Routing-INCY-HAPP/actions).

**Граница автоматизации:** YOTA публикует названия сервисов, а не полный технический перечень разрешённых доменов и IP. Совершенно новый сервис без соответствия в каталоге останется через VPN до проверки его доменов. Это не точная копия внутреннего ACL оператора. Региональные сервисы не включены: регион пользователя не указан. Их официальный перечень — [PDF YOTA](https://static.yota.ru/upload/public/doc/white_list.pdf).

GitHub может задерживать задания, приостанавливать расписание неактивного публичного репозитория или запрещать запись настройками проекта. Проверяй дату в `dist/status.json` и состояние Actions. На iPhone фоновое обновление зависит от iOS и наличия связи; оно не гарантируется ровно по часам. Если GitHub недоступен при ограничениях, нужны работающий VPN или Wi-Fi для получения обновления.

## Блокировка рекламы и Apple

Используются `geosite:category-ads-all`, AdGuard DNS через туннель и отдельные правила рекламных/аналитических доменов Яндекса, Mail и VK. Для рекламных доменов внутри разрешённых DIRECT-суффиксов дополнительно создаются DNS-блокировки. Happ получает порядок `block-proxy-direct`.

Это совместимые с Xray правила вместо загрузки несовместимого модуля blackmatrix7. DNS/доменные правила не убирают всю рекламу внутри приложений, YouTube или рекламу с того же домена, что и полезный контент. Для косметического удаления элементов сайтов можно отдельно включить блокировщик Safari.

Apple включён в `ProxySites`, а не в DIRECT. Генератор отклоняет изменения каталога, которые направили бы проверенные домены Apple напрямую. Системные исключения iOS из VPN, включая некоторые системные соединения, нельзя полностью переопределить этим профилем.

## Проверка и источники

```sh
python -m unittest discover -s . -p test_update.py -v
python update.py --repository pivazyaa/Routing-INCY-HAPP --branch main
```

Python 3.12+, только стандартная библиотека. Проверены добавление/удаление сервисов, ошибочные источники, границы доменных суффиксов, Apple через VPN, блокировка рекламы и формат импорта. Это проверки данных и генератора; на iPhone пользователя и сети YOTA в режиме ограничений профиль не тестировался.
